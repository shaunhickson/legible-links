# Legible Links (formerly LinkLens): Assessment and Path to a Public Release


_Status: approved by the owner on 2026-09-20. This document is the design record for the restructure; see `ROADMAP.md` for progress. Line numbers cited in section 1 refer to the code as it was before M0._
## Context

LinkLens (repo `youtube-url-replacer`) is a Chrome MV3 extension plus a Go backend that rewrites anchors whose visible text is a raw URL into the target's title. The goal is to make links less opaque; there is no profit motive, and the priorities are privacy, security, and ease-of-use.

The project is four months dormant (last commit 2026-05-21), has 136 commits, 105 PRs, 27 design docs, a live Cloud Run backend, CI that deploys on merge, Terraform, monitoring, Playwright, and a marketing site. It has zero users: it is not on any store, the website is not deployed, the Install button is `href="#"`, and there are no releases or tags.

This plan replaces the old six-phase roadmap. Everything below rests on reading the code (not the docs), running the test suites, probing the deployed backend, and probing the public platform endpoints the new design depends on.

## 1. Where the project actually stands

### What exists and works
- **Backend** (~2.6k LOC Go): `POST /resolve` batch endpoint, `GET /health`, per-IP rate limiter, gzip, structured logs, SSRF-aware dialer, nine resolvers (YouTube via Data API, GitHub, unshortener, Reddit, Wikipedia, Spotify, X, LinkedIn stub, OpenGraph fallback). `go build`, `go vet`, `go test -race` all pass. Deployed and responding at `https://youtube-replacer-backend-542312799814.us-east1.run.app` (health 200, CORS `*`).
- **Extension** (~1.4k LOC TS/React): content script that finds raw-URL anchors, batches them, POSTs to the backend, rewrites the anchor, shows a shadow-DOM tooltip. Popup (on/off, per-site), options page (backend URL, theme, allow/blocklist). 17 vitest tests pass, tsc and eslint clean, Playwright e2e exists.
- **Ops**: CI (lint, test, build, deploy to Cloud Run via Workload Identity), Terraform for GCP, Cloud Monitoring alerts, Dockerfile (distroless, non-root).
- **Site**: Next.js landing page with privacy policy and terms pages (not deployed anywhere).

### The core problem: the design docs promised a privacy/security posture the code does not have
`docs/DESIGN_SECURITY_AUDIT.md` mandates "no innerHTML", "html tokenizer not regex", "logs never contain full URLs". The privacy policy says "we do not store the IP address". None of that is true in the code. Ranked findings:

**Security (must fix before anyone installs)**
1. **Stored XSS on every page the user visits.** `extension/src/content.ts:176` does `element.innerHTML = \`${iconSvg}<span>${title}</span>\`` with a backend-supplied title. The backend's `resolvers/util.go:56-60` even un-escapes `&lt;`/`&gt;` back into `<`/`>`. Anyone who can post a raw link (to a page whose `<title>` they control) into a comment, email, or forum gets script execution in the origin of whatever page the LinkLens user is reading (Gmail, GitHub, a bank). Confirmed by three independent reads.
2. **Title spoofing / phishing amplifier.** The one honest thing about a raw link (its URL) is replaced by attacker-controlled text. No domain shown next to the title, original URL not kept in a `title` attribute, no bidi-control stripping, no length cap. A phishing href can render as "Sign in to your Google Account".
3. **Rate limiter bypass.** `middleware/ratelimit.go:89-94` keys on the *first* `X-Forwarded-For` entry, which the client supplies. Anyone can rotate it and use the public backend as an unlimited SSRF-constrained fetch relay (each request fans out to up to 50 outbound fetches).
4. **SSRF gaps.** `transport/safe.go` misses `0.0.0.0`/`::` (unspecified; reaches localhost on Linux), `100.64/10`, multicast, `192.0.0.0/24`, `198.18/15`; no port allowlist; JSON resolvers have no response size limit; `transport.AllowLocalIPs` is an exported unsynchronized global.
5. **No server timeouts** (`http.ListenAndServe` on DefaultServeMux; slowloris), data race in the rate limiter's cleanup goroutine, unbounded in-memory cache, one goroutine per URL with no pool.
6. **Over-broad extension permissions**: `scripting` and `activeTab` are unused; `tabs` adds a separate "read your browsing history" install warning and is not needed; `host_permissions` is `http://*/*` + `https://*/*`.

**Privacy (the product's own promises are broken)**
7. **Full URLs are logged** on any resolver failure (`resolvers/manager.go:90,98` via `log.Printf`). OpenGraph fails constantly, so this is the common path. Go's `*url.Error` also embeds the URL in error strings.
8. **Every resolved URL is stored forever in plaintext.** `firestore.go:63` writes `"original": url` next to the hashed key, with no TTL and no cleanup. The hash therefore protects nothing. Measured on 2026-09-20: the `video_titles` collection holds **15,432 documents**, oldest 2026-01-30, newest today. The 30-day request log shows ~5,700 calls from two IPs with one Mac Chrome user agent, so this is almost certainly the owner's own browsing, captured by the sideloaded extension.
9. **Client IP and User-Agent are logged on every request** (`middleware/logging.go:42-43`). Separately, Cloud Run's platform request logs record client IP regardless of application code unless a log exclusion is configured. The policy's "we do not store the IP address" is false at both layers.
10. **The visited page's origin leaks to the backend.** The fetch is made from the content script, so the browser attaches `Origin: <site you are reading>`. The backend learns which site you are on, per request.
11. **One-time links get consumed.** The extension sends *every* raw-URL anchor on *every* page (including webmail) and the backend GETs it. Password-reset, magic-login, unsubscribe, invite, and calendar links are fetched by a Google Cloud IP the moment they are rendered. No sensitive-URL filter, no skipping of `contenteditable`, no stripping of tracking params.
12. **No first-run consent.** Nothing tells the user that URLs leave the browser before the first request fires. Chrome Web Store and Firefox AMO both require disclosure for this.

**Robustness**
13. `YOUTUBE_API_KEY` empty means the backend silently returns `"Mock Title for Video X"` in production (`resolvers/youtube.go:19,60`).
14. The LinkedIn resolver is a stub returning "LinkedIn Post" and shadows the OpenGraph fallback (`resolvers/linkedin.go`).
15. A page with more than 50 raw links resolves nothing (client sends one batch; backend 413s the lot). Only the first anchor per URL is ever replaced (`content.ts:89` dedupe bug). Cache hits lose `platform`/`description`.
16. The latest commit (five resolvers, "Issue #93") shipped with zero tests. `content.ts` and `ui.ts` have zero unit tests. `basic.spec.ts` silently hits the live backend because its route mock pattern is wrong.

**Not shippable as-is**
17. No store listing, no assets, no `browser_specific_settings` (cannot submit to Firefox), no `homepage_url`, popup title still "YouTube Replacer", version skew (manifest 1.0.0, package.json 0.0.1, roadmap 0.2).
18. Website not deployed, so there is no privacy-policy URL to give the stores.
19. Repo hygiene: `.gitignore` line 22 contains literal `\n` characters so `backend.log` and `extension.zip` (a Jan-2026 pre-rebrand build) are committed; `test.html` at root is a stale duplicate.
20. Terraform drift: declares GCR image while CI pushes to Artifact Registry; uptime check targets a hostname that does not exist; YouTube key lands in local, unmanaged state.

### Process observation
The design-first, two-PRs-per-feature workflow produced a lot of scaffolding (Terraform, monitoring, gzip, Playwright fixtures, TDD guidelines, five token-gated social resolvers) for a product nobody has used, while the core loop has the defects above. For a solo project with AI agents, keep design docs for architectural changes only; put small designs in the PR description. Add a `CLAUDE.md`/`AGENTS.md` alongside `GEMINI.md`.

## 2. Strategic recommendation

### Reframe the architecture: local-first, hover for the rest
Today every raw link on every page is proxied through one server. For a privacy-first product that is the wrong default: it makes the author's server a partial browsing-history feed and makes the server act on links the user never clicked.

Proposed model, one simple mental model for the user:

| Tier | What | Where resolved | Default |
|---|---|---|---|
| 0. URL-derived | Wikipedia (`/wiki/Go_(language)`), GitHub (`/owner/repo`, issues, PRs, blobs), Reddit (`/r/sub/comments/id/title_slug`), Stack Overflow, Amazon product slugs | Pure string parsing in the browser; **no network at all** | Automatic |
| A. Platform | YouTube, Spotify, X, Reddit, Vimeo | From the service worker via each platform's public keyless oEmbed endpoint, `credentials: 'omit'` | Automatic |
| B. Everything else | Generic page titles, unshortening bit.ly/t.co | The backend (shared instance or self-hosted); small, stateless, keyless | On hover only (user intent); toggle for automatic |
| Never | Sensitive-looking URLs | Nowhere; never leave the browser | Always |

Keyless endpoint check (2026-09-20, plain GET, no credentials):

| Platform | Endpoint | Result |
|---|---|---|
| YouTube | `youtube.com/oembed?url=…&format=json` | 200, `title` + `author_name` |
| Spotify | `open.spotify.com/oembed?url=…` | 200, `title` |
| X | `publish.x.com/oembed` (`publish.twitter.com` now 301s there) | 200, `author_name` + tweet text inside `html`; long-term availability uncertain |
| Reddit | `reddit.com/oembed?url=…` | 200, title inside `html`; the `.json` API returns 403 to non-browser clients, so oEmbed with Tier 0 slug fallback |
| Wikipedia | `/api/rest_v1/page/summary/…` | 200, but unnecessary: title is in the path (Tier 0) |
| GitHub | `api.github.com/repos/o/r` | 200, but 60 req/h per IP; Tier 0 for automatic, API only on hover |

So the backend's YouTube Data API key, Twitter bearer token, Spotify client credentials, and LinkedIn token are all unnecessary. Unshortening and generic titles must stay server-side: a client-side `fetch` cannot read a cross-origin redirect's `Location`, and fetching arbitrary pages from the browser is itself a prefetch leak to every destination.

Why this default:
- No single party sees everything. Tier 0 sends nothing; Tier A sends only a content ID to the platform that hosts it; Tier B contacts the server only after a user gesture.
- Ease-of-use stays: the links people most want decoded (videos, threads, repos, Wikipedia articles) resolve instantly, most with no network.
- The store listing can say truthfully: "By default LinkLens never contacts our server without you hovering a link."
- The backend still earns its keep for unshortening and long-tail titles, but becomes optional, keyless, and trivially self-hosted.
- Settings stay small: `platformMode: 'hover' | 'auto'` (default `auto`) and `genericMode: 'off' | 'hover' | 'auto'` (default `hover`). Tier 0 is always on (no network). Onboarding shows three cards:

| Card | Tier 0 (no network) | Tier A (platform) | Tier B (LinkLens server) |
|---|---|---|---|
| **Private** | automatic | on hover | never |
| **Balanced** (recommended) | automatic | automatic | on hover |
| **Everything** | automatic | automatic | automatic |

### Product principles going forward
- **The URL is never hidden.** Rendered as `[icon] Title · domain`, real URL in the tooltip and `title` attribute. For unshortened links the *final* domain is the headline.
- **Nothing leaves the browser without a reason the user would recognize.** Sensitive-URL filter, no rewriting inside editable areas, tracking params stripped, fragments dropped, text/href domain mismatch (a phishing pattern) never rewritten.
- **Fail open.** Backend down means raw links stay raw.
- **No secrets, no state.** Backend needs no API keys and stores nothing durable.
- **Ship, then listen.** After release, build only what users ask for.

## 4. Explicitly dropped from the old roadmap

- Enterprise pillar (Jira/Linear/Notion, SSO, audit logs, "monetization"): no profit motive; conflicts with keyless/stateless.
- Viewport pre-fetching (#88): it is exactly the prefetch leak this design exists to avoid.
- IndexedDB cache (#87): `storage.session` plus a `Map` suffices; a persistent URL→title store is itself a history file.
- Safari (#92): separate toolchain and Apple account; revisit only on demand.
- LinkedIn resolver (stub, no public API), Twitter Data API, Spotify client credentials, YouTube Data API key: replaced by oEmbed or dropped. Reddit `.json` resolver (blocked): replaced by oEmbed plus Tier 0.
- Firestore, Redis, `videoIds` legacy API, Terraform, Cloud Monitoring alerts (no on-call, no users).
- Per-resolver toggles (#85) and "custom resolvers" (#86): replaced by the three-mode choice plus `apiUrl`.
- `optional_host_permissions` flow and `webextension-polyfill`: unnecessary complexity.
- Automated store publishing (#90) for v1: manual upload; automate once there is a second release.
- The two-PR design-then-implement ritual for small changes.

## 5. Verification

**XSS is fixed** (`render.test.ts`, `ui.test.ts`): render `title = '<img src=x onerror="window.__pwned=1">'` and `'"><svg onload=…>'`; assert no `img`/non-icon `svg`/`script` inside the anchor, `textContent` contains the literal `<img`, `window.__pwned` undefined. ## 8. Testing strategy (revised 2026-09-20)

The old suite had the shape backwards: Playwright fixtures for shadow DOM and infinite scroll, but zero tests on the code that inserts remote text into pages, and an end-to-end test that silently called production. The revised strategy puts the weight where the risk is.

**1. One executable privacy contract.** `extension/src/privacy-contract.test.ts` is a single table-driven vitest suite that runs the real optimizer against real DOM and asserts, for each row, exactly one of: *sent to the backend*, *resolved locally*, *left untouched*. Rows cover every guard (sensitive query keys, path segments, private hosts, editable contexts, text/href mismatch, tracking-param stripping, page-host rules, each mode). It is the specification; the README and the privacy policy may only claim what this file proves. Any new guard or resolver adds rows here first.

**2. Unit tests for every sink and every guard, written first.** `sanitize`, `render`, `ui`, `sensitive`, `cache`, each resolver, and the service-worker router get their own vitest file with XSS payloads, bidi overrides, and malformed responses. ESLint bans `innerHTML`/`outerHTML`/`insertAdjacentHTML` so the sink cannot return.

**3. Backend: unit + in-process integration, plus fuzzing and a security lint policy.** `httptest` upstreams exercise the SSRF dialer (including redirects into private space), the rate limiter under spoofed headers, and the log scrubber. `ExtractMetadata` and the URL validator get Go fuzz targets with a seed corpus (run briefly in CI). `.golangci.yml` enables `gosec`, `bodyclose`, `noctx`, `errcheck`, `staticcheck`, `govet`, `gocritic` and treats findings as failures. `-race` stays on.

**4. End-to-end is a smoke layer, not the suite.** Three to five Playwright tests against the built extension in Chromium: the extension loads and rewrites a basic page; the fixture with sensitive links produces zero outbound requests; hover triggers exactly one backend call (M1). Fixtures are served over HTTP by a tiny Node server. Firefox is checked manually with `web-ext run` and `web-ext lint` runs in CI (M1).

**5. Shared fixture for the wire contract.** `testdata/resolve-response.json` is used by both the Go handler test and the vitest optimizer test so the two sides cannot drift.

**6. CI shape.** Every PR: Go (fmt, vet, golangci-lint, `go test -race`), extension (lint, tsc, vitest, build, Playwright smoke), website (lint, tsc). `main` additionally deploys. Coverage is reported, not gated.

**7. Before each store submission** the manual checklist in section 5 is walked and the result recorded in the release notes.
